# 小米睡眠候选契约取证与修复边界

核验日期：2026-10-28。仅分析公开客户端与脱敏字段关系；不包含账号凭据、原始健康记录或设备导出数据。

## 已从该产物确认

1. `SleepSegmentReport.isUncomplete` 是 `@SerializedName("is_uncomplete")` 的布尔字段。
2. `SleepSegmentEntity.setFromLocalRecord` 将 `DailyRecordItemModel.isCompleteSleep` 取反写入该字段；`setFromServerRecord` 再取反恢复本地 `isComplete`。因此它表示该客户端的睡眠完成状态，不是午睡标记，也不是修订序号。
3. `MiParsedDataRecorder.recordSleepSegment` 将设备解析结果 `AllDaySleepParseData.isSleepFinish()` 传给记录器；记录器以醒来时间作为记录时间，并设置 `isCompleteSleep`。这说明完成状态与设备睡眠记录链路相连，不证明每个云端候选的历史转换过程。
4. `DailyRecordDaoUtils.shouldSkipServerUnCompleteSleep` 防止云端未完成记录覆盖同一行已有的完整记录。
5. `DailyRecordDaoUtils.reprocessModelRecordIfNeed` 处理同 SID 的未完成睡眠：只有新记录的区间包含旧未完成记录，才清理旧记录；已上传的旧记录标记删除，未上传的旧记录本地删除。新记录可以是完整或未完成记录。本项目只采用其中更保守的“唯一完整记录覆盖未完成候选”条件。
6. `FitnessDataModel` 以 `sid + key + time` 表示云端行身份；`SleepSegmentEntity` 的数据库主键也是这三个字段。`sid + bedtime` 是本项目的逻辑候选分组，不是源端数据库主键。
7. `FitnessDataModel.deleted` 是可空布尔。`recordServerDailyDataToDB` 对缺失/空值使用 false；仅明确 true 进入删除路径。这只说明所核验客户端的解释，并非证明云端永远不漏发删除事件。
8. `SleepSegmentUtils.convertToSleepSegmentReport` 把设备 `FitnessDataId.version` 传入睡眠 payload；设备解析器也用数据 ID 的版本决定二进制解析。这条链路的 version 不是每次快照递增的云端修订计数。

## 仍未证明

- 原始睡眠外层 `update_time` 的准确生成规则、粒度及跨行顺序保证。该版本 `FitnessDataModel` 没有建模它，不能据字段名选最大值。
- 用户账号每个候选的实际生成时序；一次读取中的完成标记与更新时间关系不能证明完整状态机。
- 不同 SID 的睡眠是否重复、入睡时间改动后的身份迁移，以及重叠独立会话的来源融合规则。

## 最小修复规则

- 保持原精确分组和稳定业务 ID；不按天、时间接近程度或最长时长合并。
- 相同写入语义继续去重。内容冲突时，要求 SID 非空、key 为 sleep、category 和时区元数据一致、明确的 bedtime、所有完成标记均为实际 JSON 布尔。
- 只有完整候选的写入内容唯一，且结束时间覆盖所有未完成候选时，才整条选择完整候选。相同完整候选的分页重复不构成新冲突。
- 多个完整候选内容不同、只有未完成候选、标记未知、完整区间较短或身份条件不满足时，仍然抛出冲突。version、time、update_time 和返回顺序均不决定优先级。
- 保留该组所有有效候选的旧 ID 别名，沿用已有精确迁移逻辑；不扩大删除范围。
- 明确 deleted=true 的云端行不生成导入样本，也不转换成 HealthKit 删除计划；缺失/null/false 沿用源客户端的非删除解释。非布尔删除标记阻止睡眠解析。
- 不全局过滤 is_uncomplete=true，不把它当作午睡。独立会话继续保留；无分期会话沿用现有阻断，不能伪造阶段或静默推进游标。
- 睡眠、睡眠 HRV、呼吸频率共用同一份候选结果。

## 验收边界

- 真实修订更新、替换清理、独立午睡的实际存在与保留、历史回填仍未完整实机验收；不伪造真实健康值测试修订。已有数据保留检查不能证明该数据集中一定存在独立午睡。
