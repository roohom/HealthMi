# 同步可靠性改动

本 fork 保留上游 App、登录和 SwiftData 数据结构，集中修复同步链路。原项目来源为 [ShawnDiego/HealthMi](https://github.com/ShawnDiego/HealthMi)。

## 时间窗

`SyncWindow` 是唯一的同步时间窗定义。最近 7 天包含今天，共 7 个自然日；内部统一使用 `[start, end)`，在小米接口边界转换成既有的包含结束秒格式。增量从成功游标前一天的午夜开始回查，所有类别使用同一任务截止时刻。

取数时间窗不再充当唯一性约束。真正的记录身份由账号摘要、数据类型和业务键组成。查找已有样本还覆盖本次样本实际起止时间，包含跨午夜睡眠。

## 更新规则

- 日常活动按日期及指标标识；零值可更新，未返回的指标不会伪造成零值。
- 点采样按来源、指标和采样时间标识。
- 睡眠候选按 `sid + bedtime` 分组；分段按会话及分段开始时间标识，改变阶段或结束时间不会换 ID。
- 同一业务身份、内容相同则跳过，内容变化则递增 `SyncVersion`。版本依据本机已写入的版本递增，不能用哈希值大小、当前时间或睡眠时长推断云端修订顺序。
- 内容摘要包含实际时间、数值、单位、阶段、关联运动等语义字段，不包含原始 JSON 顺序、登录信息或旧 ID 别名。
- 使用 HealthKit 原生 sync metadata 保证同 ID 更新；原 `ExternalUUID` 保留为兼容标记。

### 睡眠的保守边界

非官方接口没有经过核验的修订字段，因此本版不把 `time` 当作版本号，也不认为更长的睡眠必然更新。

完全相同的候选记录会归并；同一 `sid + bedtime` 下若存在不同起止时间、分期或睡眠衍生指标，则本类别同步报冲突，保留已经写入的数据。缺失/重叠/越界分期和未知阶段也会停止睡眠写入，避免静默记成浅睡或删除旧分期。HRV 和呼吸频率可使用无分期的完整汇总记录，但同组冲突仍会报错。

`sid + bedtime` 是当前可解释的候选身份，并非已证明永不变化的云端会话主键。若源端修正了 bedtime，自动识别它与另一条记录属于同一次睡眠仍需真实、脱敏的接口证据；本版不通过时间接近或“同一晚”猜测合并，也不会把独立午睡合并。

## 回填和故障恢复

普通同步和回填共用一个流程，只有取数范围不同：

1. 完整拉取、解析和校验数据。
2. 计算固定 ID、版本和精确过时 UUID，原子保存待执行计划。
3. 写入新样本，并读回核对所有目标 ID、版本和内容摘要。
4. 删除明确过时的本 App 样本，再读回确认清理结果。
5. 清除计划，提交同步游标；游标保存失败要向调用者报告。

不以“本次没有返回某条数据”推断云端删除。只有完整睡眠分期明确声明的会话范围，才允许移除该会话已不再出现的旧分段。可选指标缺失不会授权整组删除。

计划使用 `Application Support/HealthMi/PendingSync` 下的原子 JSON 文件，只保存未完成操作及规范化写入内容，不保存凭据或原始接口响应。iOS 文件采用首次解锁后的数据保护。账号之间隔离；下次同步先重放未完成计划。重放复用相同版本，不会每次重试再加一。

这是可恢复、最终一致的更新，不是跨 HealthKit 与 SwiftData 的整体事务。部分批次写入或清理中断时，可能短暂保留新旧记录；成功恢复后才算本类同步完成。

压力数据在独立、禁用自动保存的 SwiftData 上下文中更新所选范围，数据和游标一次保存，失败回滚，不清空范围外历史。

## 旧数据迁移

升级时继续使用原 Bundle ID 和登录账号。旧版没有账号元数据，因此旧记录接管仅绑定升级后第一次使用的账号；曾切换账号的历史记录归属不能仅凭旧 ID 完全证明。

只查询本 App 来源的样本：普通指标匹配完整旧业务键；睡眠需匹配来源前缀、相同入睡时间的旧 `inBed` 边界，再识别该旧会话的分段。新版本保存并验证成功后才删除这些精确 UUID。无法匹配的记录保留，其他 App 来源不参与清理。没有新增 SwiftData model，因此不需要重建用户的本地数据库。

## 本地验证

```sh
swift test
xcodegen generate
xcodebuild -project HealthMi.xcodeproj -scheme HealthMi \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build-for-testing
```

`swift test` 运行原解析测试和故障注入测试：重复同步、修订值、零值与缺失字段、账号隔离、睡眠冲突、会话分段清理、部分批次失败、读回失败、清理失败后重启恢复、并发、取消、跨日/DST、压力范围更新。内存 HealthKit 替身模拟原生版本替换；这些测试不等价于真实 HealthKit/小米云端的实机验收。

`HealthMiCloudCheck` 是显式启用的真机只读取数诊断 scheme，可配合 `-only-testing:HealthMiTests/CloudContractTests` 使用。它使用手机上已经登录的账号，只输出字段名、记录条数和时间字段关系，不写入健康数据库，也不输出凭据、SID、日期或原始健康内容。普通测试 scheme 默认跳过这个检查。

## 真机签名

新建不提交的 `Config/Signing.local.xcconfig`：

```xcconfig
HEALTHMI_BUNDLE_IDENTIFIER = 你已经使用的BundleID
HEALTHMI_DEVELOPMENT_TEAM = 你的开发团队ID
```

用 Xcode 打开项目，选择已连接、已解锁的 iPhone 后按 Cmd+R。覆盖原 App，保留登录和同步进度。续签仍受免费 Personal Team 的期限限制。本机签名文件受 `.gitignore` 保护，重新运行 XcodeGen 也会保留它。
